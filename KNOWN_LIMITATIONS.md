# Known limitations

- Current dependency/security and acceptance gates are in RELEASE_GATES.md and PROJECT_ISSUES.md. Backend audits still contain one critical and six high findings; frontend has 21 high. New compatible upgrades/clean installs were blocked by automatic approval review for unestablished telemetry. ws 8.21.0 and seven newer dependency families are applied. The recorded audit predates these changes. Full backend and local Wrangler HTTP integration now pass; previous EPERM/ENOTFOUND/EACCES statements are historical.
- Production anonymous creation challenges are implemented but real per-environment Turnstile keys/widgets are not configured. LiveKit namespace isolation is implemented in source; existing deployed/unscoped calls require an ownership-aware drain. See docs/TURNSTILE_AND_MEDIA_ISOLATION.md.
- Private/password/account-only/approval/locking/revocable invitations and unban UI are implemented. Public-room guest bans follow a saved identity. Clearing browser identity can evade a public-room guest ban; invitation-only/account-only/approval policies provide stronger admission control.
- Apply the additive Supabase session-check migration before enabling production accounts. Critical actions recheck cached session status after at most 60 seconds of activity; periodic account refresh runs every five minutes. This is bounded polling, not instantaneous upstream push revocation. Expiry/revocation removes action permissions and media access; private/account-only sockets close. Real OAuth, logout/session revocation, RLS/publications and email flows need project credentials.
- Real Google Drive files, confirm forms, redirects, seeking and cookie restrictions need staging verification. Cross-site legacy delivery depends on third-party cookie support. Streaming membership and source are now rechecked within a 15-second window. Data already delivered can remain buffered by the client.
- Production call admission creates/verifies a provider room with at most six participants; existing unlimited rooms must empty before admission resumes. Real provider API limits and webhooks remain unverified. JWT expiry does not end a live call. Removal jobs back off after twelve failures and retry up to the 24-hour limit with diagnostics and bounded retention; provider outages can delay moderation. Self-hosted and Cloud revocation behavior differ.
- Application daily counters pause new work at configured counts, but do not measure Cloudflare CPU/SQL charges, SFU participant minutes, bandwidth or TURN billing. Client bitrate/byte meters are advisory. Provider account spending/usage limits still require actual account verification; free unlimited media is not claimed.
- The directory is indexed, lease-based and retry-bounded. Batched SQLite queries passed a simulation with 500 accounts and 150 friends per account. It is not sharded. High-friend-count and production concurrency/CPU/billing limits need measurement before scaling.
- Slow-reader flow control bounds application queues for negotiated clients. A peer that lies about receipts and a platform without bufferedAmount still limit what can be proven about runtime-owned buffers. Partial chunks are transient and recover by reconnecting; they are not persisted.
- Real screen capture/system audio, restrictive NAT/TURN, mobile hardware/browser behavior, LiveKit calls and a multi-version active-tab PWA upgrade remain device/staging acceptance gates. The update notice waits for old tabs to close and never interrupts an active movie.
- The eight-hour lifecycle run uses an accelerated clock. The separate real-time in-process run lasted 60 seconds. Neither is an eight-hour real-network/media soak. Node simulations do not establish production DAU capacity or actual playback drift.
- External RPC side effects cannot be atomic with room role changes. The room checks permission before dispatch and again after completion; a late friend-invite notification can exist if authorization changed during the RPC. A private-room admission grant is not installed after that change.
- Schema 3 is forward-only for active rooms. Do not roll back to a schema-1/2 Worker; drain or use a compatible rollback build. No production backup/restore or cutover has been performed.

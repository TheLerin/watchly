# Watchly public-release issue register

The source contains the fixes and controls below. Live validation still requires authorized staging services, test devices and project access. Release remains on hold while dependency and staging gates are open.

| # | Issue | Result and remaining work |
|---|---|---|
| 1 | Dependencies | **Partial.** Both updated lockfiles install offline. The legacy backend removed Axios and ten unused transitive lockfile entries, including `form-data`. Two backend and thirteen frontend package names still match prior high or critical ranges. Upgrade those copies and obtain a current registry audit. |
| 2 | Turnstile | **Source ready.** Server verification, expiry, host/action validation, replay protection and mandatory anonymous policy have local coverage. Staging preflight checks the public key. Real key provisioning and widget acceptance remain open. |
| 3 | Session-check migration | **Awaiting confirmed staging project.** The owner approved the migration only for isolated staging. Local PGlite covers caller scoping, expiry and revocation. Verify the staging project reference and access, then apply and test the approved migration. |
| 4 | Google redirects to Vercel | **Provider configuration open.** The current browser origin is already used for the callback. Callback pages bypass the PWA navigation fallback and use no-store/no-referrer headers. Verify the actual Supabase redirect allowlist and Site URL, then use an authorized staging account. |
| 5 | LiveKit isolation | **Source ready.** Namespace ownership is enforced by grants, verified webhooks and persisted removal jobs. Verify configured staging endpoints and drain only owner-confirmed old unscoped calls. |
| 6 | Render ledger resets | **Mitigated.** Production Render requires Siteverify for every anonymous creation. Matching concurrent removal requests are coalesced. Legacy state is process-local and the fallback stays single-instance with an explicit drain policy. Shared durability remains open if legacy scaling is needed. |
| 7 | Drive delivery after kick | **Fixed locally.** Current room membership and selected media are rechecked during transfer. Worker revalidates the next delivered chunk within its 15-second authorization window and cancels on denial. Render checks on a 15-second timer and uses bounded HTTPS header resolution with streamed response bodies. Verify actual Google Drive transfers in staging. |
| 8 | Media removal exhaustion | **Mitigated.** Worker retries persist for up to 24 hours, with a cap of four concurrent provider removal requests per room and longer intervals after repeated failures. Warnings and a scoped operator recovery procedure cover terminal events. A member with pending removal cannot get a new call token. Actual provider removal and alert routing need staging verification. |
| 9 | Usage limits | **Partial.** Optional Worker byte reservations now enforce the configured daily Drive cap, including a body limit. LiveKit participant-minutes, TURN bandwidth and Worker/DO costs need actual provider measurements and provider-side limits. |
| 10 | Guest ban evasion | **Mitigated locally.** The Host can kick and require approval for all new joins in one action. A guest with a fresh identity must pass approval. The regular kick still preserves the current access policy. |
| 11 | External providers | **Open.** Auth, Drive and LiveKit have an explicit acceptance matrix. Run it against the authorized staging services with test-owned accounts/files. |
| 12 | Devices and PWA | **Partial.** Chromium passed a real two-tab Workbox update test. iOS/Android devices, capture, system audio and restrictive-network TURN remain to be tested. |
| 13 | Long-session stability | **Partial.** A 12-second in-runtime workerd WebSocket pilot took 12 snapshots and recovered one reconnect with rotated proof. The pilot logged a late acknowledgement after close, so the harness now checks the socket state before sending it. Automatic review interrupted the longer run. Network and real-media measurements remain open. |
| 14 | Presence capacity | **Improved locally.** Changed friends trigger one refresh per target room, repeated changes preserve the pending deadline, and expired connections lose their subscriptions. The 500-account, 150-friends-per-account benchmark dropped from 7,907 to 3,926 SQLite statements with 10 notifications in both runs. Remote concurrency and billing measurements remain open. |
| 15 | Stale invitations | **Mitigated.** Worker rechecks current authorization immediately before sending, and the UI checks a fresh authoritative invitation projection before joining. The post-send authorization check fences private access grants. A notification already committed by Supabase can still appear if room authority changes during the RPC. |
| 16 | Slow readers | **Verified locally.** A Durable Object alarm closes an idle peer after 30 seconds without a delivery acknowledgement, including after reconstruction. Receipt age, per-connection byte limits, and queue caps bound application-side delivery. Platform-owned buffering still depends on the runtime. |
| 17 | Backup and rollback | **Partial.** Isolated SQLite restore preserves the private room, host recovery and queue state. An approved staging backup, compatible rollback and room drain still need an operational exercise. |

Verification and release decisions are summarized in RELEASE_GATES.md. The detailed staging procedures are in docs/STAGING_ACCEPTANCE.md.

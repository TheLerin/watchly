# Watchly notification sounds

Eight short effects cover room join/leave, call join/leave, local camera on/off and local microphone mute/unmute. The tones use warm sine notes with a small second harmonic and a smooth attack/decay. Durations are 110–280ms; the default effects volume is 35%.

The application pre-renders the tones into Web Audio buffers at startup, so notifications need no fetch, decoding or file download. One persistent SoundEffectsProvider owns a separate local AudioContext and output gain. Its output connects only to the local audio destination: it never creates a MediaStream destination, captures a stream or publishes to LiveKit. It never accesses movie playback or volume.

Trusted pointer/keyboard input unlocks the context under the browser's autoplay rules. Blocked, suspended or disabled effects are skipped immediately, without replaying old notifications later. Unsupported Web Audio and unavailable local storage fail quietly. Provider cleanup releases sources and the context, including React Strict Mode replay.

## Settings

Room settings contains a Sound section in both Classic and Cinema:

- Sound effects: master ON/OFF.
- Room join sounds: room arrivals and confirmed departures.
- Voice sounds: call arrivals/departures and local camera/microphone actions.
- Effects volume: 0–100%, default 35%.

All options are saved under `watchly-sound-settings` in localStorage. Categories retain their selections while the master is OFF; dependent controls are disabled. Preferences are independent of appearance, movie volume, microphone gain and account settings. Other tabs receive local storage changes without reconnecting any media/session provider.

## Event handling and recovery

RoomContext uses the existing `user_joined` and `user_left` events and stable member IDs. Snapshots establish silent baselines. Duplicate IDs and self-joins do not play effects. The existing join payload now includes a server-computed `resumed` flag; the existing leave event retains its original first argument and adds reason/memberId as a second argument. This distinguishes real departures from transport loss, including when the observer joined while the returning member was offline. No new Socket.IO event, channel, request or polling is added.

LiveKit effects use the existing shared Room's participant and connection events. Initial participants establish a silent baseline. Reconnecting states suspend notifications; full restart repopulation and buffered duplicate arrivals stay silent. Confirmed client-initiated departures/removals produce leave cues; unknown/network disconnect reasons remain silent so an outage cannot sound like a real departure. Remote call cues are observed while this client is connected to the shared call, without auto-joining or opening microphone access.

Local action feedback runs after successful explicit camera, microphone and call actions, using actual SDK state before/after. Failed permissions, repeated no-op actions, concurrent duplicate requests, device changes, automatic track restoration and provider cleanup do not produce local camera/mic sounds. These cues are never generated by another user's camera or mute events. The retained legacy voice mode also has local join/leave/mute cues and stable-ID remote presence handling; its existing presence event receives reason/memberId metadata.

Transport drops/browser disappearance are deliberately not treated as confirmed departures. Deploy the updated backend and frontend together for precise room departure/resume classification. No environment variables or credentials are added.

## Verification

- Frontend lint/build and all 118 unit tests pass; all 58 backend tests pass.
- Chrome and Edge connect to the official local LiveKit 1.13.7 SFU. Only microphone/camera capture hardware is synthetic; signaling, publications, decoded video and PCM are real.
- Web Audio sources verify one room join for the observer and zero self-join cues, local/remote call joins and confirmed leaves, local-only camera/mic cues, master/category OFF behavior, default 35% volume and saved 20% output gain in a new tab.
- Full LiveKit restart (new participant SID), signal recovery and real Socket.IO transport recovery produce no notification sources. Initial participants, layout/theme changes and snapshots remain quiet.
- Effects create zero capture destinations. Remote microphone PCM resumes on unmute and remains silent on mute while the acting client plays its local cues. Movie playback continues.
- Existing 32-transition local-file/session lifecycle, floating-call, fullscreen and resize checks pass. Playback/legacy voice/appearance and responsive drawer regressions also pass.

Testing used local SFU transport and synthetic devices; deployed Cloud and physical Safari/iOS audio hardware were not exercised in this pass. JSON evidence and screenshots remain in ignored test artifacts.

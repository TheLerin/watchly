# Security review — 26 November 2026

The controls below have the stated local evidence; this is not production security sign-off. Full failures and external gates remain in TEST_REPORT.md and KNOWN_LIMITATIONS.md.

- Server-owned membership and roles authorize every room mutation. Shared safeEvents validates payloads, ACKs, byte/rate bounds and exceptions on both transports. Native version/ID/sequence/event/connection checks fence replay and cross-room commands.
- Host admission supports public or invitation-only entry, passwords, account-only entry, locking and approval. Invitation tokens are random, bounded, hashed and revocable/expiring; raw tokens appear only in the creation response and recipient URL. Approval queues are bounded and private. Existing proof-based members can resume without replaying new-admission checks. Public anonymous identity resets remain an inherent ban-evasion boundary.
- Password records use random salts and PBKDF2-SHA256 at 600000 iterations; creation/verification occurs outside room serialization with attempt limits and policy-revision fencing. Actual workerd validates the KDF. No password, digest or salt appears in public snapshots. Password/invitation material is excluded from durable ACKs.
- Supabase getUser verifies identity. Production also invokes the own-session security-definer function against auth.sessions, and critical activity rechecks a 60-second cache. Apply the additive migration before production accounts. Five-minute token re-supply renews presence leases; expiry/revocation clears permissions, stops screen signaling/shares, queues call removal and closes private/account-only sockets. Revocation is bounded polling, not instantaneous push awareness.
- Account JWTs are transient and omitted from durable connection records. Reconstructed account-owned mutations request fresh credentials. Reconnect proofs are stored as hashes and rotate across sockets; a 30-second previous-proof grace applies only to a disconnected member. Media authorization requires the current proof, active membership and matching fresh account.
- Room storage schema 3 migrates atomically, guards against unsafe old-worker rollback, diffs selected tables and gates event delivery on successful persistence. On write failure it quarantines state, closes sockets and reconstructs from committed records. Corrupt/future state fails closed.
- Auth/KDF/invite/provider/presence/removal I/O runs outside the serialized room queue and checks live authority before applying results. A remote invitation RPC cannot be atomic with a concurrent local role change: notification side effects may already exist, but the private-room grant/result is rejected if authority changed.
- Fixed-shard trusted-IP/account budgets protect allocation and sensitive operations. A separate durable daily counter gates new rooms, social lookups and call-token admissions. These are application counters, not provider usage/billing enforcement or a universal DDoS guarantee.
- Selected Drive file grants, HttpOnly expiring cookies, active-member checks, per-hop HTTPS allowlists, bounded redirects/caches/in-flight work and cancellation protect streaming. The optional fixed Render bridge requires a short HMAC bound to file/method/Range. Real Google and cross-site cookie acceptance remains open; an existing stream is not forcibly cut off by a later kick.
- LiveKit join tokens are short, room/identity scoped and limited to microphone/camera. Production verifies CreateRoom maxParticipants <= 6 before minting. Administration grants remain server-only. Signed webhook issuer/algorithm/expiry/body-digest checks and durable deduplication guard events. Removal jobs retry with watchdog/jitter, stop after twelve failures and retain bounded terminal diagnostics. Provider outages delay removal; token expiry alone does not disconnect calls.
- Native delivery receipts bound application pending bytes/queues, chunk large snapshots and recover incomplete transfers by reconnecting. Runtime bufferedAmount is checked when available. This cannot prove a hard runtime-buffer limit against dishonest receipt peers on every platform. Receipt/control traffic is bounded separately.
- Presence uses versioned outbox delivery, source ordering, indexed friend-authorized lookup, leases and targeted retry-bounded notifications. It reveals status, not room codes. The single directory still needs real high-friend-count/concurrency profiling.
- Cache/Origin/private API boundaries and minimum compatible CSP/nosniff/referrer headers remain. Origin is CSRF protection, not authentication. PWA updates wait and notify without taking over active sessions. Diagnostics aggregate bounded categories without tokens or identities and persist no telemetry.

Remaining release verification: clean installation/audit, separately blocked HTTP/legacy wire suites, real Supabase/OAuth/email/Drive/LiveKit/webhooks/TURN and mobile capture/audio/PWA upgrades. No billing, account, DNS, migration or deployment was changed. No paid WAF/challenge service was provisioned.
